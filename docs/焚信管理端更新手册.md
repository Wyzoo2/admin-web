### 功能变化（供运维了解，不需要操作）

1. **新增 5 个页面**：消息管理、焚毁记录、已读统计、在线监控、系统设置；仪表盘增加焚毁与在线指标。
2. **在线状态**：管理端每 60 秒向 `POST /auth/devices/:deviceId/heartbeat` 发一次心跳（仅标签页在前台时），用于保持本机在线、刷新"最后活跃"。
3. **强制下线保护**：在线监控/账号详情里，"当前设备"的强制下线按钮被禁用；其余设备需要手工输入设备记录 ID / 手机号才能提交。
4. **登录页移除「记住账号密码」**：不再在本地保存明文密码；老版本留在浏览器里的 `burnmsg_remembered_account` 会在打开登录页时自动清除。
5. **列表页筛选全部走服务端**：关键字、设备类型、时间范围等不再由前端过滤，后端接口需支持对应查询参数（见 §3）。

### 关键：后端地址是**构建期**注入

`.env` 中的变量会在构建时写死进 JS，**改完必须重新 `npm run build`**，重启 Nginx 无效：

```
VITE_API_BASE_URL=http://112.4.135.254:19091/api/v1
```

- 生产环境请把这里换成正式后端地址（形如 `https://<域名>/api/v1`），改完重新构建。
- 若该变量缺失，代码里有兜底地址（内网 IP），**不建议**依赖兜底，务必显式配置。
- 页面与后端不同源时，后端需允许该来源的 CORS（含 `Authorization` 请求头与 `OPTIONS` 预检）。

## 3. 上线前检查（后端依赖）

本版前端会调用以下接口，**缺少任一接口会导致对应页面报错**（页面会提示后端返回的错误文案，不会白屏）：

| 模块 | 接口 |
|---|---|
| 消息管理 | `GET /admin/messages`、`GET /admin/messages/:id`、`POST /admin/messages/:id/destroy` |
| 焚毁记录 | `GET /admin/destroy-records`（`stage=pending_purge` 为待真删队列） |
| 已读统计 | `GET /admin/read-stats/conversations/:id`、`GET /admin/read-stats/messages/:id` |
| 在线监控 | `GET /admin/presence/overview`、`GET /admin/presence/devices`、`POST /admin/devices/:deviceId/offline`、`GET /presence/online` |
| 仪表盘焚毁概览 | `GET /admin/stats/burn-overview` |
| 系统设置 | `GET /admin/settings/retention` |
| 心跳（本机保活） | `POST /auth/devices/:deviceId/heartbeat` |
| 既有模块 | `/auth/*`、`/accounts*`、`/groups*`、`/announcements*`、`/feedback*`、`/app-versions*`、`/audit-logs`、`/stats/overview` |

其它需要后端满足的约定：

- 统一响应 `{ code: 0, message, data }`；`code != 0` 时前端直接把 `message` 弹给用户。
- **分页上限**：`/admin/*` 与 `/presence/online` 的 `pageSize` 不得超过 **100**（超了直接 400）；`/accounts`、`/audit-logs` 可到 200。
- 登录账号必须 `role = 'admin'`，否则前端会提示"该账号不是管理员"并退出。
- 后端需支持 `/admin/presence/devices` 的 `keyword`（手机号/昵称服务端过滤）。

## 4. 部署

目标是"把 `dist/` 目录作为静态站点根目录"，并配置 SPA 回退（刷新子路由不能 404）。

### 4.1 Nginx 参考配置

```nginx
server {
    listen 80;
    server_name admin.example.com;

    root /usr/share/nginx/html/admin-web;   # 指向 dist 的内容
    index index.html;

    # SPA 回退：/messages、/presence 等前端路由刷新时仍返回 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 入口文件不缓存，保证发版立即生效
    location = /index.html {
        add_header Cache-Control "no-store, no-cache, must-revalidate";
    }

    # 带哈希的静态资源长缓存
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    # 图标等静态图片
    location /images/ {
        add_header Cache-Control "public, max-age=86400";
        expires 1d;
    }

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1k;
}
```

> ⚠️ 如果前面还有一层 CDN / 反代缓存了 `index.html`，发版后用户会继续加载旧版 JS → 表现为"页面没变化"。请对 `index.html` 关闭缓存或做版本化。

### 4.2 替换步骤（建议保留上一版）

```powershell
# 1) 备份上一版（示例）
Copy-Item -Recurse -Force D:\deploy\admin-web D:\deploy\admin-web.bak-20261027

# 2) 覆盖新产物（先清空，避免旧哈希文件堆积）
Remove-Item -Recurse -Force D:\deploy\admin-web\*
Copy-Item -Recurse -Force D:\Burning_Inquiry\admin-web\dist\* D:\deploy\admin-web\

# 3) 校验文件与权限
Get-ChildItem -Recurse D:\deploy\admin-web
```

### 4.3 建议启用 HTTPS

- 浏览器只在 **HTTPS 或 localhost** 下提供 `navigator.clipboard`；HTTP + 内网 IP 时前端已降级用 `document.execCommand('copy')`，功能可用，但建议仍上 HTTPS。
- 若采用 HTTPS，后端 API 也应为 HTTPS，避免混合内容被浏览器拦截。

## 7. 运行时行为与容量提示

- **心跳**：每个打开的管理后台标签页每 60 秒发 1 次 `POST /auth/devices/:id/heartbeat`（标签页切到后台时不发）。多开标签页会各自持有一条设备记录，属预期行为。
- **不做自动轮询**：在线监控、消息管理等列表页都是"打开时加载 + 手动刷新"，不会定时刷数据。要实时看在线变化需手动点「刷新」。
- **首屏体积**：单 JS 包约 1.5 MB（gzip ≈ 490 KB），内网访问无压力；若走公网建议开启 gzip/br 并考虑后续做路由懒加载。
- **图标缓存**：浏览器会缓存 favicon，更新 logo 后需要用户强制刷新才能看到。
- **本地存储**：仅保存 token（`burnmsg_access_token` / `burnmsg_refresh_token`）、用户信息、当前设备标识与主题偏好；**不再保存账号密码**。

## 8. 已知限制（不影响上线，可供排障参考）

1. `GET /admin/settings/retention` 的 `PUT` 后端尚未实现 → **系统设置页为只读**，保存按钮不出现，页面会显示后端返回的 env 说明。
2. `/admin/presence/devices` 不返回 IP 字段 → 在线监控没有 IP 列（文档里的 IP 展示暂缺）。
3. `/stats/overview` 没有「今日活跃设备」→ 仪表盘未展示该指标。
4. 管理员强制下线后，被踢设备若刚发过请求，可能因后端鉴权缓存还有约 **30 秒**可用窗口（实测 `+0s/15s` 仍 200、`+30s` 才 401），这是后端未失效缓存导致，前端无法规避。
5. 无心跳的设备被判离线存在延迟：`ONLINE_TTL=150s` + 后端扫描粒度，实测约 **240 秒**才转离线。
6. `GET /presence/online` 只返回**在线用户**，不支持按设备类型筛选；按设备类型筛选请用「按设备」视图。

## 9. 常见问题排查

| 现象 | 排查方向 |
|---|---|
| 打开是白屏 | 检查 `index.html` 是否被反代返回了旧内容；浏览器控制台看 `assets/index-*.js` 是否 404（部署时漏了 `assets/` 目录或 base 路径不对） |
| 登录提示「网络异常」 | `.env` 里的后端地址是否可从前端机器访问；CORS 是否允许该来源 |
| 登录后立刻跳回登录页 | token 无法刷新：确认后端 `/auth/refresh-token` 可用；或浏览器禁用了 localStorage |
| 各页面提示 404 / "Cannot GET /api/v1/admin/..." | 后端版本过旧，缺少 §3 中的接口 |
| 列表一直空 | 后端无数据，或分页参数被拒（`pageSize > 100` 会 400） |
| 刷新子页面变 404 | Nginx 缺少 `try_files $uri $uri/ /index.html` |
| 复制 ID 提示「复制失败」 | 页面是 HTTP + 内网 IP（非安全上下文）：前端已降级调用 `execCommand`，仍失败说明浏览器禁用了剪贴板（如企业策略），建议启用 HTTPS |
| 发版后页面没变 | `index.html` 被 CDN/反代缓存，或浏览器缓存；处理见 §4.1 与 §6 |
